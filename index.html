ActionPlan Kit
Spec-driven development for Claude Code

How does the ActionPlan Kit workflow work?

Plan the work, resolve questions together, build, verify and review. The workflow aims to batch human input at clarification and final sign-off; unresolved blockers are recorded.

Initintent interview — why, who, market
Planstory, acceptance criteria, checklist
ClarifyALL open questions, one batch
Buildevery task; blockers parked, never guessed
TestQA-DEV loop by a different agent
Review🔔 one poke — you sign off last

What keeps ActionPlan Kit honest

Fresh-context QA

A different agent reads only the diff — 7–8 line brief in, 7–8 line report back. It can't inherit the builder's assumptions.

Static gates that ratchet

7 selftested gates: requirement→test tracing, no plan ids in code, DoD before archive, dead-link detection. Ratchets flag new violations against the recorded baseline.

The Mirror

make status ends with computed verdicts: "6 of 14 criteria have no test. You are shipping hope." No number, no line.

One session per file

File locks stop parallel AI sessions colliding. Works across tools — the rules ship in both CLAUDE.md and AGENTS.md.

Decision memory

DECISIONS.md stops the next cycle "fixing back" a deliberate choice. Sliced by script, never read whole — token-cheap.

Real-browser QA

Playwright walk with six lenses — Broken, Confusing, Wrong, Leaky, Findable, Off-brand — plus a committed e2e scaffold.

Frequently asked questions

What is ActionPlan Kit?

ActionPlan Kit is an open-source toolkit that adds a spec-driven workflow to Claude Code. An installer drops /ap:* commands, focused review agents, static gates and plan storage into an existing repository, so work moves from a written story to verified changes and a human sign-off.

How do I install ActionPlan Kit?

Clone the repository, then run ./install.sh --target ../my-repo --code AP against the repository you want to equip. It needs Bash, Make and Node.js 22 or 24. The installer does not run Git and does not install packages, so you review and commit the changes yourself.

What is spec-driven development in ActionPlan Kit?

Work starts with a written story, acceptance criteria and a checklist. Those requirements guide implementation, test evidence and review before a human signs off.

How is it different from prompting Claude Code directly?

A plain prompt leaves the requirement, the evidence and the review in chat history. The kit writes them to files in the repository: acceptance criteria are traced to tests, QA is run by a separate agent on the diff, gates run on every check, and decisions are recorded so the next cycle does not undo them.

Which AI coding tool does ActionPlan Kit support?

The kit provides native /ap:* commands and focused agents for Claude Code. It also installs CLAUDE.md and AGENTS.md instructions for tools that read them; other tools may need manual workflow adaptation.

Which focused review agents are included?

Four focused reviewers check acceptance coverage, caller regressions, security boundaries and cleanup. They report findings without editing code. A separate QA agent reviews the diff, and the orchestrator handles fixes.

Can I add ActionPlan Kit to an existing repository?

Yes. The installer targets an existing repository and preserves its existing Makefile. Run kit gates directly with node .actionplan/scripts/check.cjs. The installer does not run Git or install packages.

Does passing verification mean the code is bug-free?

No. Gates and reviews check specific requirements and supplied changes. They provide evidence for review, but cannot prove the absence of bugs. Human sign-off remains required.

Is ActionPlan Kit free to use?

The kit is open source under the MIT license. AI tool and model usage may have separate costs. You can support maintenance through GitHub Sponsors.
